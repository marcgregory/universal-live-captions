# ADR 0005: Testing Strategy — xUnit with Fakes at Hardware Boundaries

Date: 2026-07-31

## Status

Approved

## Context

The audio pipeline depends on hardware (audio devices) and on a speech engine (Whisper model), which are non-deterministic in CI/local unit testing. The product still requires automated tests for audio initialization, device discovery, PCM buffering, sample conversion, device failure/recovery, STT transcript handling, caption state, and overlay behavior. Deterministic tests require mocking or faking at the boundaries where real hardware/STT is used.

## Decision

Use **xUnit** for all automated tests. Define stable boundary interfaces in `UniversalCaptions.Core` (`IAudioCapture`, `ISpeechToTextEngine`, etc.) and test implementations against **fakes of those boundaries** (e.g., a fake `IWaveIn` implementing NAudio's capture interface). Capture sources are constructed with an injected `IWaveIn` so tests can pump synthetic PCM bytes and raise device errors without hardware. Integration paths are verified by chaining fakes across stages; real-device and real-model verification is performed manually and recorded in `TEST_REPORT.md`.

Run commands: `dotnet build UniversalCaptions.slnx`, `dotnet test UniversalCaptions.slnx`, `dotnet format --verify-no-changes`.

## Consequences

- Deterministic unit coverage for buffering, conversion, resampling, VAD, meter, error mapping, STT handling, and caption state.
- Hardware/model behavior is explicitly verified manually (recorded evidence), not silently assumed by unit tests.
- Boundary interfaces double as the architecture contract, enforcing the separation in ADR-0003.
- NAudio remains isolated behind `IWaveIn`/`IAudioCapture`, keeping tests fast and hermetic.

## Alternatives Considered

- **Moq/NSubstitute for all mocking**: usable, but hand-written fakes of the small `IWaveIn` boundary surface are clearer and avoid dynamic-proxy dependency debates; Moq remains acceptable within the approved stack if needed later.
- **Real-device integration tests in CI**: non-deterministic and environment-dependent; rejected for the automated suite, retained as manual verification.
- **MSTest/NUnit**: equally capable; xUnit matches the bootstrap's convention and ecosystem defaults.
