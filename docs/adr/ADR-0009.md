# ADR 0009: Windows Credential Manager Is the Gemini API-Key Source of Truth in the App

Date: 2026-08-08

## Status

Approved

## Context

The Gemini Live Translate A1–A6 real-wire integration passed validation on 2026-08-08 (12/12
utterances, 0 errors, real Tagalog translations, no API-key leakage — see
`docs/spikes/GEMINI_MODEL_DISCOVERY.md`, `artifacts/spike-result/spike-result.json`). The
wire-protocol surface is frozen.

The current App-side API-key plumbing, however, is unsafe for a public release:

- `LiveTranslationEngineFactory.Create` reads the key from the `UC_GEMINI_API_KEY` environment
  variable (`LiveTranslationEngineFactory.cs` line 59 today). The value persists in the process
  environment for the App's lifetime, shows up in any tooling that reads the child-process env,
  and can be leaked through a stack trace, log, exception message, or developer `.env` file.
- The Constitution (§5) and `SECURITY_PLAN.md` §"Secret Management" already forbid committing
  secrets, and explicitly require cloud API keys to be stored via the OS credential manager. The
  factory's env-var path is a stop-gap from the A6 spike that no longer has a justification.
- A Gemini API key was previously exposed in the repository context (`AQ.Ab8RN6…`); that key
  must be revoked in Google AI Studio and a replacement key must be stored only in the Windows
  Credential Manager, never in chat, source, `.env`, `settings.json`, or any document.

## Decision

1. **Windows Credential Manager (advapi32 `CredWriteW` / `CredReadW` / `CredDeleteW`) is the
   single source of truth for the Gemini API key in the App.** The key is stored under the target
   name `UniversalCaptions:GeminiApiKey` with `CRED_TYPE_GENERIC` and
   `CRED_PERSIST_LOCAL_MACHINE`.

2. **The App reads the credential once at the start of a Gemini session and drops it from active
   memory on engine Dispose / Stop.** Argos-only sessions never load the key. The previous
   in-App `UC_GEMINI_API_KEY` environment-variable fallback is removed.

3. **The raw key never enters `UserSettings`, `settings.json`, source code, logs, exception
   messages, telemetry, or the clipboard.** Settings UI shows only a "Configured" / "Not
   configured" status; the key itself is never displayed. The key-capture modal uses a
   `PasswordBox` (SecureString-backed memory in WPF) and clears `PasswordBox.Password = ""`
   before disposing; the local `string` reference is dropped immediately after
   `SetCredential(...)` returns. Practical goal: minimum lifetime, minimum copies, no UI exposure
   (we do not claim cryptographic erasure of every managed-string copy).

4. **Updating the key while a Gemini session is running does NOT mutate the active session's
   credential.** The new value applies on the next Gemini Start. This is a deliberate trade-off
   documented in §Consequences below.

5. **The developer direct-wire spike runner (`tools/GeminiDirectWireSpike/Program.cs` and
   `tests/UniversalCaptions.Speech.Gemini.Tests/Spikes/GeminiDirectWireSpike.cs`) keeps the
   `UC_GEMINI_API_KEY` environment-variable path** for offline wire testing. This is a developer
   tool only, never shipped to end users.

## Consequences

**Positive**
- The Constitution §5 secrets rule and `SECURITY_PLAN.md` §"Secret Management" policy are fully
  enforced at the App layer.
- No `.env` file is required in the user-facing App path. The App cannot accidentally persist the
  key, log it, or display it back to the user.
- Per-entry Credential Manager isolation: a single compromised entry does not expose other
  settings; the key is encrypted at rest by the OS credential store (DPAPI under the user
  profile).
- Minimum-lifetime policy: the key exists in managed memory only during a Gemini session.
- The Settings UI exposes `[Add API key…]` / `[Update…]` / `[Remove]` with a clear status —
  user-controlled rotation and removal.

**Negative**
- Adds a Win32 P/Invoke seam (`advapi32.dll`) to `UniversalCaptions.App/Settings/`. The Core
  project remains pure (no platform dependencies); only the App project, which already uses
  WPF, owns the credential seam.
- Requires an in-process `InternalsVisibleTo("UniversalCaptions.App.Tests")` declaration so the
  test assembly can use the `internal InMemoryCredentialStore` and `WindowsCredentialStore`
  types. The test-only types are kept out of the public API surface.
- Removing the env-var fallback is a breaking change for any in-repo developer code that read
  `UC_GEMINI_API_KEY` from the App — there is none today, but the change must be called out in
  the changelog and reviewed in the close-out pass.

**Trade-offs**
- Live-session credential update is intentionally NOT supported. If a user clicks `[Remove]`
  while a Gemini session is active, the running engine continues with its in-memory credential
  until the user clicks Stop. The next Start picks up the change. This avoids mid-flight
  WebSocket re-handshake complexity and keeps the wire protocol frozen (no A6 surface change).
- No automatic env-var fallback for the production App — by design. A missing credential
  surfaces as "translation does not activate" rather than a fallback read of an environment
  variable that may have leaked from elsewhere.

**Neutral**
- `UC_LIVE_TRANSLATION_PROVIDER`, `UC_GEMINI_MODEL`, `UC_GEMINI_SYSTEM_INSTRUCTION`, and
  `UC_GEMINI_ENDPOINT` remain environment-variable-driven. They are not secrets; they are knobs.
- Schema bump: `UserSettings.CurrentVersion` advances from `1` to `2` to record the new
  `TranslationProvider` enum field. The bump is load-tolerant — `SettingsStore` ignores unknown
  fields and returns defaults on `JsonException`, so existing v1 settings files load as
  `TranslationProvider = Argos` (the default).

## Alternatives Considered

- **Plaintext settings file (`settings.json`):** rejected. Constitution §5 explicitly forbids
  committing secrets, and a plaintext file is the obvious leak vector. Same reasoning for
  DPAPI-encrypted settings entries — they widen the blast radius (one app blob decrypts all
  settings; Credential Manager isolates per entry).
- **DPAPI-encrypted settings entry:** rejected. Broader attack surface than per-entry Credential
  Manager isolation.
- **OS keyring NuGet library (e.g., `Meziantou.Framework.Win32.CredentialManager`):** rejected.
  The BCL `System.Runtime.InteropServices` covers `advapi32` P/Invoke directly; adding a
  third-party package for one entry point is unjustified.
- **Cloud-stored key:** rejected. The App is offline-first; routing the key through a cloud
  service contradicts the product's privacy model.
- **Keep `UC_GEMINI_API_KEY` as a fallback for developer convenience:** rejected for the App
  path. The fallback stays in the developer spike runner (tool, not product).

## Implementation Outline

See `docs/implementation/CHANGELOG.md` v0.5.30 (in progress) and the Security Test Cases
section of `docs/SECURITY_PLAN.md` for the test gate. Code changes:

- `src/UniversalCaptions.App/Settings/ICredentialStore.cs` (new, public interface).
- `src/UniversalCaptions.App/Settings/WindowsCredentialStore.cs` (new, internal,
  advapi32 P/Invoke).
- `src/UniversalCaptions.App/Settings/InMemoryCredentialStore.cs` (new, internal, test fake).
- `src/UniversalCaptions.App/LiveTranslationEngineFactory.cs` — swap `UC_GEMINI_API_KEY` read
  for `ICredentialStore.TryGetCredential`; new ctor signature.
- `src/UniversalCaptions.App/App.xaml.cs` — register `ICredentialStore` in the DI composition
  root; pass it into the factory closure.
- `src/UniversalCaptions.App/UniversalCaptions.App.csproj` — `<InternalsVisibleTo
  Include="UniversalCaptions.App.Tests" />`.
- `src/UniversalCaptions.App/Settings/UserSettings.cs` — new `TranslationProvider Provider`
  field; `CurrentVersion` 1 → 2.
- `src/UniversalCaptions.App/Controls/ControlWindow.xaml` + `.xaml.cs` — Translation provider
  combo + `[Add API key…]` / `[Update…]` / `[Remove]` buttons + status indicator.
- New tests: `InMemoryCredentialStoreTests`, `WindowsCredentialStoreTests`,
  `LiveTranslationEngineFactoryTests`; one new `SettingsStoreTests` for the v1 → v2 migration.

## Revocation Checklist

The previously exposed `AQ.Ab8RN6…` key (fingerprint `AQ.Ab8RN`) is **invalid** the moment
the user clicks "Replace API key" in Google AI Studio. The replacement key:

1. Lives in Windows Credential Manager only, under `UniversalCaptions:GeminiApiKey`.
2. MUST NOT be pasted into chat, `.env`, `settings.json`, source, or any document.
3. MUST NOT be committed to the repository in any form, including test fixtures, spike logs,
   or screenshots.
