# ADR 0004: WPF Always-on-Top Caption Overlay and Separate Control Window

Date: 2026-07-31

## Status

Approved

## Context

The product needs an always-on-top caption overlay that is borderless, has a configurable transparent background, is draggable, resizable, has adjustable opacity and font size, configurable position, multi-monitor awareness, and an optional click-through mode. The overlay must be visually separate from the control UI (audio source, language, engine, start/stop, status, latency, settings).

## Decision

Implement the caption overlay as a **WPF window** hosted by `UniversalCaptions.App`, exposed through an `IOverlayService`. Use a separate WPF window for the control UI. Achieve always-on-top with `Topmost`, transparency via `AllowsTransparency` + background transparency, click-through via Win32 `WS_EX_TRANSPARENT | WS_EX_LAYERED`, and multi-monitor placement via the Windows screens/DPI APIs. `UniversalCaptions.Captions` owns caption state; the overlay only renders it.

## Consequences

- Native transparent, borderless, always-on-top behavior without web technologies.
- Per-monitor DPI is available through WPF's `PerMonitorV2` support (Windows 10 1703+).
- Click-through mode is opt-in and implemented with a small P/Invoke surface in the App project.
- The overlay and control window share caption state through `ICaptionService`, keeping responsibilities separated.
- Overlay behavior is partially hardware/OS-dependent; unit tests cover `ICaptionService` logic, with overlay verification via manual checks and WPF-level tests where feasible.

## Alternatives Considered

- **WinForms**: weaker support for transparent layered windows, per-monitor DPI, and borderless overlay polish. Rejected.
- **WebView2 overlay**: heavier; requires WebView2 runtime; no benefit for a text overlay. Rejected.
- **Direct2D/DirectWrite custom rendering**: maximal control but significant custom windowing work for the MVP. Rejected for MVP; not ruled out for future polish.
