# ADR 0002: WASAPI Loopback Audio Capture (No VB-CABLE)

Date: 2026-07-31

## Status

Approved

## Context

The application must capture audio playing through Windows from arbitrary applications (browsers, conferencing, media players, games) and render captions. The product brief explicitly requires that the MVP not depend on VB-CABLE or any virtual audio cable, and that it not depend on Chrome or Chrome Live Caption.

The OS-native mechanism for capturing the system render mix is WASAPI loopback capture (`AUDCLNT_STREAMFLAGS_LOOPBACK`), which records whatever is playing through an output device.

## Decision

Use **WASAPI loopback capture** via NAudio's `WasapiLoopbackCapture` as the primary capture mechanism, wrapped behind an `IAudioCapture` abstraction in `UniversalCaptions.Audio`. The MVP captures the default render device (system mix). VB-CABLE is rejected as a requirement and is only a possible optional input in a later milestone behind the same abstraction.

Target minimum OS: Windows 10 build 17763 (1809) — WASAPI loopback and NAudio support this baseline.

## Consequences

- No virtual audio cable is required to receive system audio.
- Loopback receives the mixed output of the selected render device, so per-application separation is not available in the MVP.
- Exclusive-mode and content-protected streams are not available to loopback (documented OS limitation, risk R-001).
- Capture is hardware-dependent and must be verified manually on real audio; unit tests use a fake `IWaveIn` boundary.
- Device disconnects surface through `RecordingStopped` with an exception and are mapped to user-readable errors.

## Alternatives Considered

- **VB-CABLE as primary capture**: violates the explicit product requirement; rejected.
- **Chrome Live Caption**: only works inside Chrome; explicitly excluded.
- **Custom raw WASAPI COM interop**: more control but far more code; NAudio already provides a maintained, Windows-10-compatible wrapper.
- **Microphone capture**: not applicable — the product captures system audio, not the microphone; microphone capture is out of scope and requires explicit enablement in any future release.
