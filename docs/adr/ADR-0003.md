# ADR 0003: Streaming Speech-to-Text Abstraction with Local Whisper as First Engine

Date: 2026-07-31

## Status

Approved

> **Superseded in part (2026-08-05) by [ADR-0008](ADR-0008.md):** the production STT default is now
> the faster-whisper native streaming engine with live partials. The "default model is ggml-base"
> clause below is superseded; ggml-base remains available as the explicit fallback
> (`UC_STT_ENGINE=ggml-base`). The streaming `ISpeechToTextEngine` abstraction and engine-neutrality
> rationale remain in force.

## Context

Captions require continuous, low-latency speech recognition producing partial (in-progress) and final transcripts. The application must not be coupled to a single recognition provider, and privacy requirements prefer local/private processing: audio should not leave the machine in the MVP.

Local Whisper (whisper.cpp) was selected as the first engine direction by the user, but with an explicit instruction: **do not select a Whisper model size yet** — first get the audio pipeline working, then benchmark candidate models against the actual Windows 10 target hardware.

## Decision

Define `ISpeechToTextEngine` as a **streaming, engine-neutral** interface:

```text
AudioChunk
    ↓
ISpeechToTextEngine
    ↓
PartialTranscript / FinalTranscript
```

The interface must not assume Whisper-specific behavior. Concrete engines implement it:

- `WhisperSpeechToTextEngine` (local Whisper) — first engine
- `CloudStreamingSpeechToTextEngine` (future, explicit opt-in)
- additional future engines

**Contract location (refined 2026-07-31, Slice 2):** `ISpeechToTextEngine`, `PartialTranscript`, `FinalTranscript`, `SpeechRecognitionError`, and `SpeechRecognitionException` live in `UniversalCaptions.Core` (namespace `UniversalCaptions.Core.Speech`). This is required by the dependency table in `REPOSITORY_STANDARDS.md` (and by ADR-0005, which lists `ISpeechToTextEngine` as a Core boundary interface): `UniversalCaptions.Captions` (Slice 4) must consume transcripts while referencing only Core. `UniversalCaptions.Speech` owns the concrete engines (`WhisperSpeechToTextEngine` and test doubles where applicable) and depends on Core only.

Whisper model size selection is deferred until a latency/accuracy benchmark on target hardware (Slice 2/5).

**Model selection (finalized 2026-07-31, Slice 2 — user-approved, see `docs/reports/BENCHMARK_REPORT.md`):** on the target Windows 10 machine (12 logical cores, CPU/whisper.cpp):

- **Default model: ggml-base** (141 MB, ~149 MB RAM, 0.14–0.28× decode realtime factor, realtime-safe streaming, WER 4.9% on the conversational OSR sample).
- **Fallback/performance model: ggml-tiny** (74 MB, ~82 MB RAM, 0.07–0.14× decode, first final 5.3–8.2 s vs base ~10 s, but WER 16.0% on OSR). Available as a low-resource mode for machines where `base` cannot sustain realtime.
- **ggml-small rejected as the live-caption default** (465 MB, 0.88× decode / 1.76× streaming — cannot sustain realtime on this hardware); used only as the benchmark pseudo-reference.

**Default model is ggml-base for live captions; ggml-tiny remains an optional low-resource fallback.** Model selection is configurable (`WhisperEngineOptions.ModelPath`) and is **not coupled to `WhisperSpeechToTextEngine`**. The runtime may monitor performance but must **not** silently switch models; any model change is explicit user action.

Streaming finals are produced by the stability-based committer on every benchmark sample (`jfk`, `jfk` + 10 dB SNR noise, `jfk_long`, OSR).

Note: the benchmark is updated 2026-07-31 with four samples (`jfk`, `jfk` + 10 dB SNR noise, `jfk_long`, and the conversational OSR_us_000_0010). Streaming finals are now produced by the stability-based committer on every sample. The OSR sample discriminates model quality: **ggml-tiny 16.0% WER vs ggml-base 4.9% WER** (jfk-derived samples are 0.0% for both), which drove the user-approved default of **ggml-base** (tiny as low-resource fallback). See `BENCHMARK_REPORT.md`.

## Consequences

- The pipeline (capture → processing → captions) never depends on a specific STT vendor.
- A fake engine gives deterministic tests for the caption service without hardware or models.
- Local Whisper keeps audio on the machine in the MVP, satisfying the privacy model.
- Cloud STT, if added later, requires explicit configuration and on-screen disclosure that audio leaves the machine.
- Model selection is a benchmark decision, not an upfront commitment.

## Alternatives Considered

- **Cloud streaming STT (Azure/OpenAI)**: low local cost but streams audio off-machine; conflicts with the MVP privacy preference; requires API keys/network. Rejected for MVP.
- **Windows.Media.SpeechRecognition**: offline and OS-integrated but with a limited language set and no clean path to feed a continuous WASAPI loopback stream. Rejected.
- **Vosk**: viable streaming alternative; not selected because the user directed local Whisper as the first engine.
- **Tightly coupling to Whisper**: rejected — the abstraction is required to keep engine options open.
