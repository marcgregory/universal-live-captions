# ADR 0008: Production STT Default Is the Faster-Whisper Native Streaming Engine with Live Partials

Date: 2026-08-05

## Status

Approved

## Context

Slices 8–12 replaced the stale windowed-faster-whisper commit cadence and closed the two remaining
gaps for a Chrome-Live-Caption-style experience:

- **Accuracy:** faster-whisper `small` int8 recognizes Tagalog far better than the `ggml-base`
  default (committed WER **~33%** vs **51.2%** on the actual Tagalog lecture audio vs the `fil-orig`
  reference).
- **Responsiveness:** the native-streaming engine (Slice 10) commits one coherent FINAL per
  completed speech segment at **13.3 FINALs/120 s** (~9 s cadence) with **no 20–40 s backlog**.
- **Live partials (Slice 12):** bounded trailing-window re-decodes of the in-progress segment at a
  1 s cadence (window 4 s) raise a `PartialTranscriptAvailable` event while the speaker is still
  talking. Controlled real-audio gate **PASS**: first visible partial **5.59 s after speech onset**
  (vs first FINAL 15.0 s), **19.5 partials/120 s**, FINAL stream text-identical to Slice 11 (no
  accuracy regression), backlog bounded, realtime-safe 1.18×.

## Decision

**The production default STT path is now `FasterWhisperNativeStreamingEngine` with live partials
enabled** (partial interval 1 s, partial window 4 s, `MaxSegmentDuration` 8 s — the Slice 11 frozen
cap). This supersedes ADR-0003's "default model is ggml-base" clause.

- **Engine selection (env-driven, unchanged pattern):**
  - default / `UC_STT_ENGINE=fasterwhisper-native` → native streaming + partials
  - `UC_STT_ENGINE=ggml-base` → the original local-Whisper engine (explicit fallback)
  - `UC_STT_ENGINE=fasterwhisper` → the windowed faster-whisper engine (unchanged opt-in)
- **The ggml-base implementation is preserved** as the explicit fallback (`UC_STT_ENGINE=ggml-base`).
  There is **no automatic runtime fallback** — silently switching engines mid-session would violate
  the ADR-0003 "no silent model switch" rule; a worker failure surfaces as a caption error and stops
  the session (user can restart with the fallback).
- The faster-whisper **worker wire protocol is unchanged**; the windowed engine, ADR-0007, TD-002,
  and TD-005 are untouched.

## Consequences

- Users get Chrome-like incremental captions with materially better Tagalog recognition by default.
- Operational dependency: the native path requires the faster-whisper Python worker + `small` int8
  model (auto-discovered at `%TEMP%\fwv` or via `UC_FW_PYTHON`); ggml-base remains fully
  self-contained as the fallback.
- Documented costs of partials: ~5 % wall and ~8 s tail emit-lag versus FINAL-only (Slice 12
  benchmark); the rolling-4 s-window means the FINAL reveals the earlier words of a long segment.
- Model/engine selection stays environment-configurable and is never silently changed at runtime.

## Alternatives Considered

- **Keep ggml-base as the default with faster-whisper native opt-in** (status quo before this ADR):
  rejected by the user for this product decision because the goal is the Chrome-like experience with
  better Tagalog recognition, both now validated.
- **Promote the windowed faster-whisper engine:** rejected earlier (Slices 8–9) — its steady-state
  STT latency (13.7–15.8 s vs ggml-base 2.4–3.7 s) is a live-caption responsiveness regression, and
  it retains the stale-commit cadence the native engine eliminates.
- **Automatic runtime fallback to ggml-base on worker failure:** rejected — silent engine switching
  contradicts ADR-0003 and would hide availability problems.

## Supersedes

Partially supersedes **ADR-0003** (the "default model is ggml-base" model-selection clause). The
streaming `ISpeechToTextEngine` abstraction and engine-neutrality rationale remain in force.
